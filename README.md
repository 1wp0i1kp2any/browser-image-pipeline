# browser-image-pipeline

Самостоятельная браузерная библиотека (TypeScript) конвейера изображений:

```
изображение → геометрия → (шарп) → квантование палитры → кодирование
подбор:     изображение → геометрия → перебор параметров до первого влезшего в предикат
```

Встроенные форматы: `image/jpeg` (MozJPEG), `image/png` (+ oxipng),
`image/webp` (libwebp), `image/avif` (libaom) — все через публичный реестр.

Библиотека **не знает**, где она будет использоваться: ни UI, ни фреймворков,
ни знания о лимитах веса, data:URL или белых списках MIME. «Сжать до заданного
веса» — не её задача: библиотека даёт ступени и перебор, а рамку веса
и решение «подходит / не подходит» приносит вызывающий код предикатом.

Поставка — исходники: `src/` (ядро + кодеки + квантование), `test/`,
этот README, `demo/` (живой стенд, в пакет не входит).

## Быстрый старт

```ts
import { image } from 'browser-image-pipeline';

// Прямое использование: ступени выбирает вызывающий.
const out: Blob = await image(blob, async (p) => {
  await p.frame({ width: 200, height: 200, fit: 'cover' }); // cover — накрыть и обрезать
                                                            // по центру; contain — вписать
  await p.quantize({ colors: 64, dithering: 0.5 });          // опционально
  return p.encode('image/png', { quality: 0.9 });            // → Blob заявленного формата
});

// Подбор: рамку веса знает только вызывающий — она приходит предикатом.
const hit = await image(blob, (p) =>
  p.fit(
    {
      formats: ['image/jpeg', 'image/png'],   // порядок = порядок предпочтения
      quality: [0.8, 0.99],                   // [пол, потолок]
      colors: [16, 256],                      // диапазон палитры (опционально)
      frame: { width: 200, height: 200, fit: 'cover' }, // геометрия первым шагом
    },
    (candidate) => candidate.size <= LIMIT,
  ),
);
// hit: { blob, params: { format, quality, colors?, channel? }, attempts } | null
// null — не влезло даже на полу (минимальное качество × минимальные цвета).
```

Каждый вызов `image()` независим; глобального состояния обработки нет.

## Ступени

### `p.frame({ width, height, fit })`

Геометрия. `cover`: меньшая (относительно) сторона дотягивается до целевой,
большая обрезается по центру — результат ровно `width × height`.
`contain`: кадр вписывается целиком с сохранением пропорций, результат
может быть меньше по одной стороне (полей библиотека не дорисовывает).
Масштабирование вверх разрешено. EXIF-поворот честится при декодировании
(`createImageBitmap(..., { imageOrientation: 'from-image' })`).

Метод ресемплинга — `method`: `'bilinear'` (по умолчанию), `'lanczos3'`
(sinc-окно a=3 с масштабированием ядра при уменьшении — самый резкий
даунскейл фото, выбор Squoosh/Sharp), `'area'` (точное интегрирование по
площади пересечения пикселей, лучший анти-муар). Все три метода работают
в premultiplied-альфе: невидимый RGB полностью прозрачных пикселей не
окрашивает видимых соседей.

Реализация — чистый TS (ресайз + кроп), без canvas: детерминированно
между браузерами (вес не «плавает» от сглаживания конкретного движка)
и тестируемо в Node. Плата — скорость на исходниках в десятки мегапикселей;
ступень по контракту идёт первой, дальше кадр уже целевой.

### `p.sharpen({ amount?, radius? })`

Unsharp mask. Классический «output sharpening»: мягкий шарп (0.2..0.6)
после frame-даунскейла возвращает воспринимаемую резкость, которую ресайз
неизбежно смягчает.

### `p.quantize({ colors, dithering })`

Срез палитры до `colors` цветов (2..256). **Формат не меняется**: палитра —
свойство пикселей, энкодер получает уже квантованный кадр. По умолчанию
палитру строит image-q (WuQuant, расстояние pngquant), применение —
собственный Floyd–Steinberg с непрерывной силой `dithering` ∈ [0, 1]
(у image-q «силы» нет, только выбор алгоритма; `0` — чистый nearest,
детерминирован бит-в-бит). Дополнительно выбираются: алгоритм палитры
(`wuquant` | `rgbquant` | `neuquant` | `neuquant-float` |
`fast-median-cut`), формула цветового расстояния (`pngquant`, `ciede2000`,
...) и serpentine-проход дизеринга. `fast-median-cut` — собственный
детерминированный median-cut без image-q: на benchmark-корпусе строит
палитру в разы быстрее и не проигрывает необъяснимо по MAE/SSIM, но
остаётся opt-in, а `wuquant` — качественным умолчанием. Честная оговорка:
rgbquant в image-q падает на плавных градиентах (метод подрегионов требует
повторяющихся цветов) — библиотека оборачивает это в понятную ошибку.

### `p.encode(format, options?)`

Кодирование через реестр «формат → кодек». `options.quality` нормировано
0..1 (кодек сам отображает в свою шкалу), `options.channel` — канал кодека
(см. ниже), остальные поля пробрасываются кодеку как есть:

```ts
await p.encode('image/jpeg', { quality: 0.9, channel: 'grayscale', progressive: true });
// channel → MozJPEG color_space (тот самый «Channels» из Squoosh)
```

Нормированные (межформатные) опции:

| Опция | jpeg (MozJPEG) | webp (libwebp) | avif (libaom) | png |
|---|---|---|---|---|
| `quality` 0..1 | 0..100 | 0..100 | 0..100 | — (lossless) |
| `subsampling` | 4:4:4 / 4:2:0 (chroma_subsample 1/2) | только 4:2:0 (иначе ошибка) | 4:4:4/4:2:2/4:2:0/4:0:0 | ошибка |
| `effort` 0..1 | trellis-оптимизации | method 0..6 | speed 10..0 | уровень oxipng 0..6 |
| `lossless` | ошибка | lossless 1 | lossless-флаг | всегда |
| `channel: 'grayscale'` | color_space | обесцвечивание кадра | обесцвечивание + 4:0:0 | обесцвечивание кадра |

Шкалы качества форматов **не эквивалентны** (AVIF 0.6 визуально крепче
JPEG 0.6) — сравнивайте метриками, а не числами. Поля конкретного кодека
пробрасываются и старше нормированных отображений: у MozJPEG это
`quant_table` (0 Annex K, 1 flat, 2 MS-SSIM, 3 Robidoux — умолчание
сборки), `trellis_*`, `smoothing`, `separate_chroma_quality`; у libwebp —
`sns_strength`, `filter_*`, `alpha_quality`, `use_sharp_yuv`, `exact`,
`target_size`/`target_PSNR`; у AVIF — `tune` ('ssim'/'psnr'/'auto'),
`denoiseLevel`, `sharpness`, `chromaDeltaQ`, `enableSharpYUV`,
`qualityAlpha`; у PNG — `oxipngLevel` 0..6 и `oxipng: {interlace,
optimiseAlpha}`. Замеренная честность: поле `near_lossless` текущая
сборка @jsquash/webp **игнорирует** (размеры при 0/60/100 идентичны) —
«почти без потерь» делайте палитрой 256 + lossless (и помните: на плавных
градиентах палитра lossless-кодекам вредит, см. таблицу ниже). Роль quality
в lossless тоже замерена: у WebP она остаётся параметром упаковки
(декодирование побитово точно при любом q, размер слегка меняется), у AVIF
игнорируется полностью (сам энкодер предупреждает об этом). Поэтому fit по
таким плоскостям качество не ищет — делает одну пробу на фиксированном
верхнем q, а режим объявляет через capabilities кодека (ниже).

Незарегистрированный формат → `UnknownFormatError`; неподдерживаемый канал →
`UnsupportedChannelError`. Молча работать не так, как попросили, библиотека
не умеет.

### `p.fit(spec, fits, { strategy }?)`

Перебор до первого влезшего в предикат `fits(candidate)`. Порядок перебора —
по «визуальной цене» размерностей (см. «Размерности поиска»): внутри
плоскости качество режется вглубь до пола spec, затем пробуются каналы,
в последнюю очередь — глубокая палитра. Форматы — в порядке spec.

`spec.frame` (или предварительный `p.frame(...)`) настоятельно рекомендуется:
без геометрии вес при одном качестве зависел бы от исходника, а не от
параметров. Если геометрия не задана нигде, подбор идёт по кадру исходного
размера — пример из ТЗ работает, но это редко то, что нужно.

В поиске квантование выполняется **без дизеринга**: его шум ломает
монотонность кривой «цвета → вес», на которой стоят стратегии. Возвращаемый
блоб — одна из проб как есть (перекодирования «начисто» нет).

Fit принимает явный бюджет: `maxAttempts` (реальные энкоды; кэш проб не
считается) и `deadlineMs` от входа в `fit()`. Дедлайн проверяется перед
следующей пробой — уже запущенный энкод доработает, прервать wasm нельзя.
По умолчанию исчерпание бюджета бросает `FitBudgetExhaustedError`
(`reason/attempts/elapsedMs`): пробел в поиске не должен притворяться
доказанным «ничего не влезло». `onBudgetExhausted: 'return-null'` — явный
opt-in к старому стилю. Обычный `null` теперь означает строго: пространство
поиска исчерпано и подходящего кандидата в нём нет.

Диагностика поиска — предупреждения, а не молчание: событие
`warning`/callback `onWarning` сообщает о неподдержанных кодеком значениях
каналов/субсемплинга (fit отфильтровывает их и продолжает; прямой `encode`
по-прежнему бросает), о свёрнутой оси качества (PNG и lossless-режимы) и о
принудительной замене стратегии на `owner-loop`.

Кроме встроенных измерений, fit принимает именованные категориальные
`spec.dimensions`: независимые наборы опций кодека, которые движок сам
перемножает плоскостями и возвращает в `params.dimensions` (см.
«Размерности поиска»). Стратегию качества можно передать не только именем,
но и функцией/объектом — её власть ограничена одной плоскостью и сеткой
quality (см. «Стратегии подбора»).

## Реестр энкодеров (публичный API расширяемости)

```ts
import { registerEncoder, type Codec } from 'browser-image-pipeline';

const webp: Codec = {
  channels: ['rgba'],                       // что кодек принимает в options.channel
  capabilities: {                           // опционально: семантика quality для fit
    quality: true,          // false — fit не ищет по quality и не передаёт его
    qualityRole: 'quality', // 'quality' | 'effort' | 'ignored'
    monotoneQualitySize: true,
    qualityStep: 0.01,      // шаг внутренней шкалы: кэш проб не дублирует энкоды
    // можно функцией: (options) => options.lossless ? { qualityRole: 'effort' } : undefined
  },
  async encode(frame, options) { /* frame: {data,width,height} → Blob */ },
  async decode(blob) { /* опционально */ },
};
registerEncoder('image/webp', webp);
```

Для изоляции вместо глобального реестра создайте отдельный и передайте
его конкретному вызову:

```ts
import { createEncoderRegistry, defaultEncoderRegistry, image } from 'browser-image-pipeline';

const registry = createEncoderRegistry(); // пустой; или копия: createEncoderRegistry(defaultEncoderRegistry)
registry.register('image/webp', webp);
await image(blob, pipeline, { registry });
```

Встроенные `image/jpeg` (@jsquash/jpeg), `image/png` (@jsquash/png +
@jsquash/oxipng), `image/webp` (@jsquash/webp), `image/avif`
(@jsquash/avif) регистрируются в default-реестр **тем же механизмом** и не
привилегированы: потребитель может заменить кодек формата одной
регистрацией. Изолированный реестр по умолчанию пуст, поэтому регистрации
параллельных вызовов с одним MIME друг в друга не протекают. Кодек может
дополнительно декларировать `subsampling: [...]` — поддерживаемые значения
`options.subsampling` (fit пересекает со spec), и `capabilities` — какая у
него ось качества: обычная, quality-as-effort (lossless-упаковка),
игнорируемая или отсутствующая. Кодеки без `capabilities` (включая уже
написанные потребительские) работают как раньше: quality поддерживается и
считается монотонным. Новый алгоритм = новая регистрация, ядро не
правится; смена формата у потребителя — аргумент, не правка кода. Двойное
перекодирование не нужно и не делается: кадр один, энкод последний.

Встроенная семантика оси качества в fit:

| Формат/режим | quality в fit |
|---|---|
| JPEG/WebP/AVIF lossy | ищется по сетке, шаг кэша 0.01, вес считается монотонным |
| WebP lossless | quality-as-effort: одна проба на верхнем q сетки |
| AVIF lossless | игнорируется энкодером: одна проба, quality не передаётся |
| PNG | quality нет: одна проба, quality не передаётся |

## Стратегии подбора

Стратегия ищет качество на **общей сетке** (шаг 0.01 в пределах
`spec.quality`; обе границы диапазона сохраняются точно, внутренние
точки не выходят за диапазон) внутри одной плоскости параметров
(формат × палитра × канал);
порядок плоскостей у всех стратегий один. Допущение: вес монотонен по
качеству и числу цветов, предикат пороговый по весу (типично
`candidate.size <= LIMIT`). Тогда все стратегии находят **одну и ту же**
лучшую влезшую точку, что и `owner-loop`, — «не хуже базового цикла»
выполнено по построению и проверяется тестами на равенство параметров,
а отличаются стратегии только числом энкодов. Если предикат не пороговый
(например, зависит не от веса) — честный выбор `owner-loop` или явный
`monotonicity: 'none'`: fit тогда сам заменяет запрошенную умную стратегию
на `owner-loop` внутри каждой плоскости (с предупреждением) и не делает
никаких монотонных выводов из проб. Дополнительно умные стратегии
страхуются: если вес пола оказался больше веса потолка, наблюдаемая
монотонность сломана — поиск внутри плоскости откатывается к `owner-loop`
(пробы вилки переиспользуются кэшем). Это страховка от инверсии на концах,
а не доказательство монотонности внутри.

### Своя стратегия качества

`FitOptions.strategy` принимает имя, функцию или объект `{ name?, search }`:

```ts
import type { FitQualityStrategy } from 'browser-image-pipeline';
import { assertQualityStrategyMatchesOwnerLoop } from 'browser-image-pipeline/testing';

const myStrategy: FitQualityStrategy = async (probe, grid, context) => {
  // context: plane, planeIndex, signal, attempts(),
  // remainingAttempts(), elapsedMs(), maxAttempts, deadlineMs
  for (let i = grid.length - 1; i >= 0; i--) {
    const out = await probe(grid[i]);
    if (out.fits) return { quality: grid[i], blob: out.blob };
  }
  return null;
};

await p.fit(spec, fits, { strategy: myStrategy });
```

Контракт жёсткий: пробовать можно только точки переданной сетки, вернуть
можно только Blob реально выполненной пробы с `fits=true`, а форматами и
порядком плоскостей стратегия не управляет. Сам Blob-предикат ей не
отдаётся — только размер и вердикт пробы. Отдельный subpath
`browser-image-pipeline/testing` даёт harness для авторов стратегий
(`evaluateQualityStrategy`, `compareQualityStrategyToOwnerLoop`,
`assertQualityStrategyMatchesOwnerLoop`) на синтетических монотонных
кривых.

| Стратегия | Идея | Худший случай на плоскости [0.80..0.99] |
|---|---|---|
| `owner-loop` | Базовый цикл заказчика: качество 0.99→0.80 линейно, первый влезший — return; затем цвета пополам и снова качество. Каналы вставлены между качеством и палитрой (у исторического цикла их не было). | 20 проб × число плоскостей |
| `binary` ⭐ умолчание | Вилка (потолок влез — готово за 1; пол не влез — плоскость мертва за 2), дальше бинарный поиск границы по сетке. | ≤ 7 проб; мёртвая плоскость — 2 |
| `secant` | Та же вилка + ложное положение по весу: линейная интерполяция в координатах (1/q, ln size) к геометрической середине весов вилки. Для JPEG вес близок к линейному по 1/q — предсказание попадает в границу за 1–2 пробы. Порог предиката неизвестен, поэтому целимся не «в лимит», а в середину весовой вилки. | как binary; обычно на 0–1 пробу меньше |
| `coarse-fine` | Пробы пола (мёртвая плоскость — 2 пробы), затем редкая сетка сверху (каждая ~4-я точка), первый влезший грубый интервал уточняется бинарно. Сильна, когда граница обычно высоко. | чуть хуже binary в худшем, лучше при высокой границе |

Замерено (`npm run bench`, синтетический кодек с модельной кривой веса
~1/(1.02−q), монотонной по качеству/цветам/каналам; пробы до попадания,
результат у всех стратегий одинаков):

| Сценарий | owner-loop | binary | secant | coarse-fine |
|---|---|---|---|---|
| лёгкий кадр, щедрый лимит | 1 → q0.99 | 1 → q0.99 | 1 → q0.99 | 1 → q0.99 |
| фото, граница ≈ q0.87 | 13 → q0.87 | 7 → q0.87 | 6 → q0.87 | 8 → q0.87 |
| фото, граница у пола | 19 → q0.81 | 6 → q0.81 | 6 → q0.81 | 7 → q0.81 |
| фото, нужна палитра | 120 → q0.80 c16 | 16 → q0.80 c16 | 16 → q0.80 c16 | 17 → q0.80 c16 |
| шум (худший энтропийный случай) | 119 → q0.81 c16 | 16 → q0.81 c16 | 16 → q0.81 c16 | 17 → q0.81 c16 |
| манга (монохром, grayscale разрешён) | 32 → q0.88 grayscale | 9 → q0.88 grayscale | 8 → q0.88 grayscale | 10 → q0.88 grayscale |
| невозможный вес | null (120) | null (12) | null (12) | null (12) |

Сверка на **реальном MozJPEG** (шумный кадр 200×200, поиск только по качеству,
сетка 0.50–0.99):

| Лимит | owner-loop | binary | secant | coarse-fine |
|---|---|---|---|---|
| 30000 B | 12 → q0.88, 29788 B | 8 → q0.88, 29788 B | 8 → q0.88, 29788 B | 7 → q0.88, 29788 B |
| 12000 B | 32 → q0.68, 11800 B | 7 → q0.68, 11800 B | 8 → q0.68, 11800 B | 9 → q0.68, 11800 B |
| 8500 B | 46 → q0.54, 8421 B | 8 → q0.54, 8421 B | 7 → q0.54, 8421 B | 9 → q0.54, 8421 B |

Выводы из замеров:

- Главный выигрыш умных стратегий — не середина сетки, а **мёртвые
  плоскости**: owner-loop платит полную сетку (20 энкодов) за каждый
  недостижимый уровень палитры, остальные — 2 пробы. Отсюда 120 → 16.
- Когда граница у самого потолка (кадр «почти влезает» на максимуме),
  owner-loop может выиграть 1–2 пробы у binary — линейный спуск сверху там
  оптимален. Умолчанием оставлен `binary`: у него лучший гарантированный
  худший случай, а проигрыш у потолка — единицы проб.
- `attempts` в результате fit — честный счётчик энкодов (тесты сверяют его
  с независимым счётчиком модельного кодека).

PNG и качество: PNG — lossless, параметра качества у него нет, и библиотека
это не маскирует. Capabilities сворачивают пустую ось в одну пробу на
плоскость; вес png режется палитрой (ступень quantize) — как раз
независимость «палитра ⊥ формат».

## Форматы и пресеты: что реально режет вес (замерено)

`npm run compare` (scripts/compare-formats.ts): каждый кандидат
декодируется обратно и сравнивается с исходником экспортируемыми
метриками `compareFrames` (PSNR, блочный SSIM по яркости, MAE). Кадр
«фото-градиент» 200×200:

| Кандидат | Вес, B | PSNR, дБ | блочный SSIM |
|---|---|---|---|
| jpeg q0.80 (умолчания сборки) | 2136 | 47.5 | 0.9933 |
| jpeg q0.80 + пресет photo (trellis) | 2027 | 47.5 | 0.9946 |
| jpeg q0.80 + пресет maxCompression (табл. MS-SSIM, smoothing) | 1778 | 49.8 | 0.9965 |
| jpeg q0.80, 4:4:4 | 2312 | 47.9 | 0.9935 |
| webp q0.80 | 800 | 42.5 | 0.9887 |
| webp q0.80 + пресет photo (SharpYUV, autofilter) | 764 | 44.4 | 0.9904 |
| avif q0.60 | 630 | 47.9 | 0.9951 |
| png (голый энкодер) | 50287 | ∞ | 1.0000 |
| png + oxipng 3 | 1536 | ∞ | 1.0000 |
| png палитра 128 + oxipng 3 | 1857 | 31.5 | 0.8200 |

Главные выводы замеров: (1) oxipng обязателен для PNG — голый rust-png
проигрывает ему в разы и десятки раз; (2) палитра на плавных градиентах
может сделать lossless **тяжелее** (ломает предсказуемость для
энтропийного кодера) — палитра для графики, не для градиентов;
(3) пресеты — стартовые точки: maxCompression на манге дал хуже блочный SSIM
(smoothing вредит линейной графике), проверяйте метриками на своём контенте.

Пресеты экспортируются: `PRESETS[format][name]` (photo/screen/
maxCompression/lossless) — наборы EncodeOptions без quality:

```ts
import { PRESETS } from 'browser-image-pipeline';
await p.encode('image/avif', { ...PRESETS['image/avif'].photo, quality: 0.6 });
```

Новые измерения fit: `spec.subsampling` (порядок предпочтения, пересекается
с `codec.subsampling`) и универсальный `spec.variants: EncodeOptions[]` —
перебор любых параметров кодека (smoothing, quant_table, tune...) в заданном
порядке после каналов/субсемплинга и до палитры; применённый вариант
возвращается в `params.variant`. Стратегии при этом не менялись — они
работают с плоскостями.

### Анализ кадра, alpha-метрики и PNG optimizer

`analyzeFrame(frame, { maxSamples?, signal? })` — чистая утилита поверх
кадра: saturation, nearMonochrome, mean luma, alpha coverage/mean alpha и
число занятых 5-битных RGB-корзин. Это приближённый индикатор разнообразия
цветов, а не «точное число цветов». Полностью прозрачные пиксели
исключаются из насыщенности/яркости/корзин; автоматический выбор формата
утилита не делает. Внутренняя проба монохрома fit использует её с тем же
порогом.

Для альфы есть отдельные метрики `computeAlphaMAE` и
`computePremultipliedMAE`; базовый `compareFrames` по-прежнему означает
RGB PSNR + блочную luma-аппроксимацию SSIM + RGB MAE и не прячет альфу
внутрь старых чисел. Метрики принимают необязательный `{ signal }`.

`optimizePngBlob(blob, { engine?, level|effort, interlace, optimiseAlpha,
onlyIfSmaller, signal? })` lossless-оптимизирует уже готовый PNG без
decode/encode. По умолчанию `engine:'oxipng'`; результат принимается только
если меньше, а если oxipng потерял входной цветовой чанк
(`iCCP/gAMA/cHRM/sRGB/cICP`), возвращается оригинал.

Альтернатива без wasm — `engine:'compression-stream'`: отдельный ленивый
модуль строго парсит PNG/CRC, пережимает только zlib-поток `IDAT` через
`CompressionStream('deflate')`, повторно распаковывает его для байтовой
проверки и сохраняет все остальные чанки в исходном виде и порядке.
Пиксели, фильтры, palette, color type и interlace не меняются по
построению. Oxipng-опции с этим движком честно отклоняются, а не
игнорируются. Удаления метаданных как скрытой опции нет.

## Размерности поиска и канал как измерение

Размерности перебора имеют разную визуальную цену, порядок это уважает:

1. **Качество** — деградация плавная, кривая веса крутая: режется первым и
   вглубь, пока разрешает `spec.quality[0]` (пол задаёт вызывающий).
2. **Канал** (`spec.channels`, opt-in) — например, `grayscale` у jpeg
   выбрасывает цветовые плоскости целиком. Для почти-монохромного контента
   это самый большой выигрыш при нулевой цене; для цветного фото —
   разрушающая мера, поэтому без явного разрешения в spec grayscale
   не пробуется никогда.
3. **Палитра до ~16 цветов** — полосатость и шум: последняя надежда
   перебора, а не второй шаг.

Форма измерения «канал» — `spec.channels?: string[]`: дополнительные
разрешённые каналы в порядке предпочтения вызывающего, после канала кодека
по умолчанию. Обоснование выбора формы:

- имя `channels` — термин самого заказчика («Channels» из Squoosh);
- значения — строки в терминах кодека (`'ycbcr' | 'rgb' | 'grayscale'`
  у jpeg, `'rgba' | 'grayscale'` у png): формат-специфика остаётся делом
  кодека, ядро значений не знает;
- кодек декларирует поддерживаемые каналы в `codec.channels` (первый —
  по умолчанию); fit пересекает spec с возможностями кодека и предупреждает
  о отфильтрованных значениях (`warning`/onWarning), а прямой `encode` с
  неподдерживаемым каналом бросает `UnsupportedChannelError`;
- у png wasm-кодек всегда пишет RGBA, поэтому `'grayscale'` у png честно
  реализован обесцвечиванием кадра перед энкодом (R=G=B сжимается лучше).

При `frame` fit делает дешёвую **пробу насыщенности** кадра (средний разброс
каналов по подвыборке ≤4096 пикселей; не HSL-S — она взрывается у почти
белых пикселей сканов). Если кадр почти-монохромный (средний разброс
≤ ~10/255) и grayscale разрешён, он поднимается сразу за канал по умолчанию —
раньше прочих каналов и задолго до палитры. Проба видна через событие
состояния `probe`.

**Именованные категориальные измерения.** Когда независимых параметров
кодека несколько, не нужно вручную собирать их декартово произведение в
`variants`:

```ts
await p.fit({
  formats: ['image/jpeg'],
  quality: [0.8, 0.99],
  dimensions: [
    { name: 'smooth', values: [
      { id: 'off', options: { smoothing: 0 } },
      { id: 'soft', options: { smoothing: 50 } },
    ] },
    { name: 'quant', values: [
      { id: 'standard', options: { quant_table: 0 } },
      { id: 'flat', options: { quant_table: 1 } },
    ] },
  ],
}, fits);
// hit.params.dimensions → { smooth: {id, options}, quant: {id, options} }
```

Измерения перечисляются плоскостями после variants в заданном порядке;
монотонность им не приписывается и бинарный поиск по ним запрещён дизайном.
Одно значение — fixed и применяется всегда. Ключи опций разных измерений
и variants не должны пересекаться (конфликт отклоняется до первого энкода);
`quality`, `channel`, `subsampling` задаются своими измерениями spec.
Числовых пользовательских осей здесь нет сознательно: они требуют явной
декларации монотонности и equivalence-тестов, а не ещё одного массива чисел.

**Расширяемость размерностей.** Внутри все измерения скомпилированы в
дескрипторы `fixed | categorical | frame-transform` (палитра меняет кадр,
остальные перечисляются плоскостями), а стратегии по-прежнему не знают про
размерности: они получают готовую плоскость и ищут внутри неё только
качество. Плоскости fit перебирает лениво (`iteratePlanes`), а их число
для события `fit-start` считается без материализации декартова
произведения — большие spec/variants/dimensions не раздувают память до
первой пробы. Полный исторический порядок плоскостей закреплён
golden-тестами.

## Состояние и отмена

```ts
const controller = new AbortController();
await image(blob, pipeline, {
  state: (event) => { /* decode-start, frame, quantize, warning,
                         fit-start (плоскости/верхняя оценка/бюджет), encode
                         (с номером попытки и параметрами), encode-done
                         (размер, вердикт предиката), probe, fit-exhausted,
                         fit-done, done, error */ },
  signal: controller.signal,
});
```

Форма доставки — **синхронный callback**. Обоснование: потребитель показывает
«идёт генерация» без опроса чего-либо (события приходят сами, в точках
прогресса); библиотека не тащит никакой реактивности и UI — вызывающий
заворачивает события в свой механизм (стор Svelte, `setState`, сигнал)
одной строкой; события сериализуемы (кроме `error.error`), их можно слать
через postMessage из воркера. Бросивший слушатель конвейер не роняет.

Если UI нужен готовый снимок, а не поток событий, есть отдельный
collector (ядро он не утяжеляет):

```ts
import { createStateCollector } from 'browser-image-pipeline/state';

const collector = createStateCollector();
const unsubscribe = collector.subscribe((snapshot) => render(snapshot));
await image(blob, pipeline, { state: collector.listener });
collector.getSnapshot(); // status, stage, attempts, warnings, timings, fit
unsubscribe();
```

Подписчики изолированы друг от друга, а снапшоты не отдают мутабельные
внутренние массивы попыток наружу.

Отмена через стандартный `AbortSignal` проверяется между ступенями, между
пробами fit и внутри длинных чистых циклов (геометрия, шарп, применение
палитры — минимум раз в 32 строки): конвейер бросает `AbortError`, bitmap
декодера закрывается всегда (finally). Уже запущенный wasm-энкод и
построение палитры внутри image-q прервать нельзя — они доработают, но
результат будет выброшен, а не отдан. Отдельных wasm-инстансов на вызов не
создаётся (инстансы @jsquash живут внутри их модулей), поэтому «отозвать»
при отмене нечего.

## Среда выполнения

Целевые платформы — актуальные браузеры (`createImageBitmap`,
`OffscreenCanvas`, WebAssembly). Фактически прогнаны Chromium, Firefox и
Playwright WebKit: полный demo-smoke, EXIF-ориентации 1–8, PNG/JPEG/WebP
со встроенным sRGB ICC, grayscale/palette/interlaced PNG, прозрачность и
анимированные GIF/APNG/WebP с документированным поведением «первый кадр»
(`scripts/browser-fixtures.ts`). Playwright WebKit — не Safari один в один:
честно заявляется проверенный WebKit-движок, а не конкретный Safari на
macOS/iOS.
Вне браузера (SSR/Node) `image()` честно бросает `EnvironmentError` — если
только вызывающий не дал свой декодер:

```ts
await image(blob, pipeline, { decoder: async (b) => /* → Frame */ });
```

`options.decoder` — шов для тестов и нестандартных сред; публичный API он
не усложняет (одна опциональная опция).

Ресурсные лимиты задаёт вызывающий: `image(..., { maxPixels,
maxDimension })` проверяет декодированный кадр и целевую геометрию frame
(включая промежуточный cover-масштаб) и при превышении бросает
`ResourceLimitError` **до** тяжёлой работы. Без лимитов поведение прежнее;
библиотека универсальный «безопасный» мегапиксель не навязывает. Дополнительно
re-sampling честно отклоняет цели, чья аллокация не влезает в typed array,
а fit удерживает не более двух квантованных кадров в кэше палитры.

OffscreenCanvas → кадр → wasm-энкод) проверяется жёстким playwright-смоуком
демо-страницы в Chromium, Firefox и WebKit; smoke падает на pageerror, console
error, HTTP ≥400, requestfailed, статусе ошибки или пустом Blob.
